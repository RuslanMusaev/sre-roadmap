# SRE Roadmap на 3 месяца

Практический маршрут развития для работающего SRE/DevOps: **12 недель, 60 заданий и занятия по 30–60 минут в день**.

Проект объединяет интерактивный план с отслеживанием прогресса и подробный практикум. В центре обучения — реальные симптомы, проверяемые гипотезы, диагностика и восстановление сервиса.

## Что внутри

- **Roadmap:** чекбоксы задач, общий прогресс, прогресс по неделям и направлениям, сворачиваемые недели и переход к следующему заданию.
- **Практикум:** подготовка, четыре шага выполнения, ожидаемые навыки, критерий готовности и вопрос для самопроверки с подсказкой для каждого из 60 заданий.
- Поиск по практикуму и фильтр по неделям.
- Сохранение прогресса в `localStorage`, экспорт и импорт прогресса в JSON.
- Итоговая лаборатория с API, PostgreSQL, Kafka, Kubernetes, наблюдаемостью и GitOps.
- Тёмный адаптивный интерфейс на русском языке; команды и технические термины оставлены на английском.

## Для кого

Для инженеров, которые уже знакомы с Linux, контейнерами и эксплуатацией сервисов и хотят системно углублять знания через небольшие практические эксперименты.

Установка сложных компонентов может потребовать нескольких сессий. План можно проходить в своём темпе: 30–60 минут — бюджет занятия, а не обязательный срок завершения каждой задачи.

## Программа

| Неделя | Тема |
| --- | --- |
| 1 | Linux internals: процессы, systemd, CPU, память, I/O и file descriptors |
| 2 | TCP/IP, DNS, HTTP/HTTPS, TLS, curl и tcpdump |
| 3 | Kubernetes: CrashLoopBackOff, Pending, Service, DNS и rollout |
| 4 | Requests/limits, probes, scheduling, HPA и PDB |
| 5 | RBAC, NetworkPolicy, storage и Helm |
| 6 | Prometheus, PromQL, Grafana, Alertmanager и SLI/SLO |

| 8 | PostgreSQL: индексы, EXPLAIN ANALYZE, locks, pools и replication |
| 9 | Kafka: partitions, groups, offsets, lag, ISR, replication и безопасность |
| 10 | Python/Bash: health checker и сбор диагностических данных |
| 11 | CI/CD, версионирование образов и Argo CD |
| 12 | Интеграция lab и три incident drill |

## Как начать

1. Скачай репозиторий через **Code → Download ZIP** и распакуй архив.
2. Открой `index.html` в современном браузере.
3. Выбери задание и перейди по ссылке «Открыть подробный разбор».
4. Выполни упражнение в своём учебном окружении, сохрани evidence и проверь критерий готовности.
5. Отметь выполненную задачу в Roadmap.

Оба HTML-файла храни рядом, чтобы переходы между ними работали.

Для просмотра не нужны установка зависимостей, сборка или сервер. Каждый HTML содержит собственные стили и скрипты. Содержание работает офлайн; установка lab-инструментов, загрузка образов и внешняя документация требуют сети.

## Прогресс и данные

Прогресс сохраняется в браузере, а не в GitHub-аккаунте. Автоматической синхронизации между устройствами нет. Перед сменой браузера, очисткой данных или переходом с локального файла на опубликованный сайт экспортируй прогресс в JSON, затем импортируй его в новом месте.

Разные сайты GitHub Pages одного владельца могут использовать общее хранилище браузера: для форков и независимых копий проекта при необходимости меняй ключ `sre-roadmap-3m-v1` в `index.html`.

В проекте нет внешних библиотек, аналитики или собственного backend. Сам учебный стенд создаётся отдельно; готовые Kubernetes-кластеры и серверы в репозиторий не входят.

## Итоговый lab

Минимальная система: HTTP API → PostgreSQL, API → Kafka → worker. Helm описывает развёртывание, CI проверяет изменения, Argo CD синхронизирует состояние из Git. Метрики, traces и logs помогают расследовать ошибки.

Результат — воспроизводимый запуск, smoke test, dashboard, alert с runbook, диагностический CLI и три incident report. Для тяжёлых упражнений практикум предусматривает явно обозначенный архитектурный разбор при ограниченных ресурсах.

Все поломки выполняй в отдельной лаборатории на синтетических данных.

## Публикация через GitHub Pages

После загрузки файлов открой **Settings → Pages** и выбери:

- **Source:** Deploy from a branch
- **Branch:** main
- **Folder:** / (root)

Сохрани настройки. После успешного развёртывания GitHub покажет ссылку на сайт в разделе Pages. Файл `index.html` должен лежать в корне выбранной папки публикации.
